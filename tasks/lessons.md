- 시드 수를 늘릴 때 동시 실행 수가 함께 늘어나는지 항상 확인한다. 6개일 때 괜찮았다고

## 빌드 타겟 실수 (2026-08-24, 사용자 지적)

**패턴**: 코드를 고친 뒤 헤드리스 eval 바이너리만 빌드하고 `bin/mjpc`(사용자가 실제로
보는 GUI)를 빌드하지 않은 채 GUI 커맨드를 줬다. 사용자가 실행했더니 변경이 없었다.
같은 종류의 실수를 그 전에도 했다: `cd mjpc/tasks/...` 한 상태에서 `cmake --build build`를
실행해 "build is not a directory"로 조용히 실패.

**규칙 (예외 없음)**
1. 빌드는 **항상 리포 루트에서** 실행한다. `cd` 후 상대경로 `build` 금지.
2. 코드를 고쳤으면 **영향받는 모든 타겟을 같은 명령에서** 빌드한다.
   task 파일을 고쳤으면 `mjpc`는 무조건 포함:
   `cmake --build build --target mjpc <eval 타겟들> -j 8`
3. 사용자에게 실행 커맨드를 주기 전에 **그 바이너리에 변경이 들어갔는지 확인**한다.
   새 env 스위치라면 `strings build/bin/mjpc | grep -c MJPC_XXX`가 0이 아닌지 확인.
   XML을 고쳤으면 `build/mjpc/tasks/.../task.xml`에 반영됐는지 grep (빌드가 source에서
   복사하므로 재빌드 전에는 build 사본이 옛 값).
4. 빌드 로그를 `grep -E "error|Linking"`으로만 보면 "타겟이 아예 안 돌았다"를 놓친다.
   Linking 줄에 **기대한 바이너리 이름이 있는지** 확인한다.

## 하나의 knob을 두 목적으로 쓰지 말 것 (2026-08-24, 사용자 지적)

**무슨 일**: `pick_app_lag`를 (1) 가이드점 전진 게이트와 (2) "파지점에 도달했다"
판정 임계값에 **동시에** 썼다. 사용자가 "lag 항 없애"라고 해서 0으로 두자
`lag < app_lag`가 항상 거짓이 되어 **닫기 명령이 원리적으로 불가능**해졌고,
되던 파지가 전부 실패했다. 이어서 하드 게이트 자체의 병리도 드러났다: "lag<문턱이면
전진"은 전진할 때마다 lag를 문턱으로 밀어올려 **경계에 고정**되고, 진행률이
0.86에서 멈춰 `s_app>=1` 조건이 영원히 안 된다.

**규칙**
1. 게이트(무엇을 허용/금지)와 판정 임계값(무엇을 달성으로 볼지)은 **항상 별도
   파라미터**로 둔다. 값이 같아도 이름을 나눈다.
2. 어떤 knob을 0/off로 만들 때, 그 값을 읽는 **모든 지점**을 grep해서 무엇이 같이
   꺼지는지 확인한다.
3. 임계 기반 하드 게이트는 경계 고정(boundary lock)을 만든다. 레퍼런스 전진에는
   **연속 감속**(full below lag_ok, zero at lag_max)을 쓴다. phase 2와 phase 3에서
   같은 버그를 두 번 만들었다.
4. 사용자가 "되던 게 안 된다"고 하면, 그 시점 이후 내가 바꾼 것을 **전부 나열**한
   뒤 하나씩 되돌려 확인한다. 되던 시드로 즉시 재현 테스트한다.

## 보고 누락 (2026-08-26, 사용자 반복 지적)

**패턴**: 백그라운드 작업을 걸어두고 "끝나면 보고하겠습니다"라고 한 뒤, 완료 알림만
기다리며 침묵. 사용자가 "왜 보고 안 해"를 여러 번 반복해서 지적했다. 사용자 입장에서는
진행 상황이 전혀 안 보이고, 이미 나와 있는 부분 결과조차 못 받는다.

**규칙 (예외 없음)**
1. **시드/조건 하나가 끝날 때마다 보고한다.** 스윕 전체가 끝날 때까지 기다리지 않는다.
   그러려면 스윕을 한 덩어리 백그라운드로 던지면 안 된다 - 완료 알림이 맨 끝에 한 번만
   오기 때문이다. **시드마다 별도 백그라운드 작업으로 띄워서** 매 완료마다 알림을 받고
   그 즉시 그 시드 결과를 보고한다.
1b. 그와 별개로, 작업 중 사용자가 말을 걸면 먼저 그 시점 부분 결과를 로그에서 꺼내 보고한다.
2. 작업이 끝났다는 알림을 받으면 **다음 메시지의 첫 부분이 결과 보고**여야 한다.
   다른 작업을 먼저 시작하지 않는다.
3. "끝나면 보고하겠습니다"라고 말했으면 그 약속은 알림이 오는 즉시 이행한다.
4. 긴 작업은 시작할 때 예상 소요와 중간 확인 방법(어느 파일을 보면 되는지)을 같이 준다.
